# Agents Guide & Workspace Rules

**agents-template**

Generator that writes AGENTS.md, CLAUDE.md and .claude/ for a project from its project.config.yml.

Type: `cli` · Stack: node · Package manager: `npm`

> Generated from `project.config.yml` by claude-template `init.mjs`. Change the config and re-run init instead of editing this file by hand.

---

## 1. Fast Reference
- `init.mjs` — orchestrator; lib/: pure parts (yaml, render, scaffold, routing), zero dependencies
- `templates/` — templates for generated projects; core/: skills, agents, rules copied into projects
- `global-skills/` — slash commands; skills/ and .claude-plugin/ are generated by build-plugin.mjs

Local-only / git-ignored (never commit):

- `.env`

---

## 2. Agent Execution Rules
1. **Commands:** Run project commands directly on the host with `npm`.
2. **Verification:** Run `node test.mjs` before marking work complete.
3. **Deployment:** Deployment is manual; pushing does not deploy. Never deploy without explicit approval.
4. **Explicit Commit & Push Only (Strict Rule):** never commit or push on your own initiative. Changes stay in the working tree until the user issues `/commit`, `/push`, `/commit-push`, `/merge-to-dev`, `/merge-to-main`, `/ship` (or asks in chat).
5. **Attribution:** Do not add `Co-Authored-By` or "Generated with" lines to commits or PRs.
6. **Branch model:** `feat/example → dev → main`. `main` is protected: never commit or push to it directly.
7. **Never** force-push, use `--no-verify`, or stage secrets (`.env`, credentials, dumps).

### Project-specific rules

- This repo is a generator, not an app. init.mjs reads a target project's project.config.yml and writes AGENTS.md, CLAUDE.md and .claude/. templates/ are the templates for generated projects; core/ (skills, agents, rules) is copied into them; this repo's own .claude/ is generated output, do not edit it by hand.
- Plain Node 18+ ES modules, zero dependencies (own YAML-subset parser in lib/yaml.mjs). lib/ stays dependency-free and side-effect-free: take target/dry/here as arguments, never read process.argv.
- Template engine is tiny: double-brace variables and if/else/endif blocks, no nested if. core/skill-map.json maps type/stack tokens to skills; a new stack = new core/skills/<name>/SKILL.md plus a map entry.
- Commands: node test.mjs (smoke suite, add --list or --only <text>), node init.mjs --target <dir> [--dry-run|--scaffold], node bench.mjs, node evals/run.mjs. bench-cost.mjs and orchestrate.mjs with a real claude SPEND MONEY, never run them without asking.
- Tests enforce: no template placeholders left in generated md/json, re-running init is idempotent (0 created, 0 updated), invalid type and forbidden words exit non-zero.
- Bump VERSION when a change should show as an upgrade (old -> new) in existing projects. Update README.md and project.config.example.yml when adding config keys. Add a CHANGELOG.md entry.
- skills/ and .claude-plugin/ are generated by node build-plugin.mjs from global-skills/ and VERSION; CI fails if stale. Enable the pre-commit hook once per clone: git config core.hooksPath .githooks.
- main and dev are protected (PR only, CI required, no force-push). PRs go to dev; only dev may be merged into main (guard-main.yml, check source-must-be-dev). Never push to them; there is no deploy.

Detailed rules live in `.claude/rules/` (architecture, commands & testing, docs, git shortcuts). Skills are in `.claude/skills/`; the skill routing for this project is in `.claude/CLAUDE.md`.

## 3. Shorthand Commands
- **`/commit [message]`**: inspect working tree, stage safely, create a Conventional Commit locally.
- **`/push`**: push the current branch to `origin` with tracking (protects `main`).
- **`/commit-push [message]`**: commit and push in one step.
- **`/merge-to-dev [message]`**: commit + push the working branch, merge into `dev`, push it, return (auto-abort on conflict).
- **`/merge-to-main`**: tests, then `dev` → `main` with one confirmation before pushing.
- **`/ship [message]`**: `feat/example → dev → main` with tests and one confirmation before pushing `main`.
- **`/pr`**: open or update a pull request without merging.
- **`/status`**, **`/sync`**: show or safely update branch state.
- **`/doc-sync [notes]`**: update `README.md` to match the changes.
