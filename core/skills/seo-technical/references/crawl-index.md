# Crawling and indexing

Verify specifics against the search engine's current documentation before quoting limits or syntax.
- **Pipeline (simplified):** discover URLs, crawl (fetch), render if needed, index (store and understand), serve. A URL can fail at any stage; diagnose which one before fixing.
- **robots.txt:** controls crawling, not indexing. [Guideline] A URL blocked in robots.txt can still appear in results without a snippet if it is linked elsewhere. To keep a page out of results use `noindex` (meta robots or `X-Robots-Tag`) on a crawlable page, or authentication. A page blocked from crawling cannot have its `noindex` read. Do not block CSS/JS/API endpoints needed to render pages [Guideline]. The file lives at the host root, applies per host/protocol, and a non-200 or unreachable robots.txt changes crawler behavior; test changes before deploy. [Requirement] Syntax follows the Robots Exclusion Protocol (RFC 9309).
- **Meta robots / X-Robots-Tag:** `noindex`, `nofollow`, `nosnippet`, `max-snippet` and related directives; use the HTTP header for non-HTML files (PDF). Conflicting directives resolve to the most restrictive one in Google's documentation (verify).
- **XML sitemaps:** list canonical, indexable, 200-status URLs only; accurate `lastmod` (only when content really changed, otherwise it is ignored); reference from robots.txt and submit in Search Console; protocol limits per file (documented as 50,000 URLs / 50 MB uncompressed, verify) with a sitemap index for more. Separate sitemaps help diagnose coverage by section. Sitemaps are hints, not commands. `priority`/`changefreq` are largely ignored [Practice, verify].
- **Canonicals:** `rel=canonical` is a hint for choosing the representative URL among duplicates; use absolute URLs, self-referencing canonicals on indexable pages, one canonical per page in the `<head>` or HTTP header, no canonical to a redirected/noindexed/404 URL, no canonical chains. Do not use canonical to merge unrelated pages. Pair with consistent internal links, redirects and sitemap entries.
- **Duplicate sources:** http/https, www/non-www, trailing slash, case, parameters (tracking, sort, session), print views, pagination, locale duplicates. Pick one form, redirect (301) the rest, link and canonicalize consistently.
- **Indexing diagnostics:** Search Console URL Inspection and Page indexing report (statuses like "Crawled, currently not indexed" and "Duplicate, Google chose different canonical" have different causes), site: queries are not reliable counts. Quality and duplication cause many non-indexed pages, not only technical errors.
- **Staging/pre-production:** block with authentication, not robots.txt alone; ensure the production build never ships `noindex` or `Disallow: /` (add a CI check, see `seo-migration-monitoring`).
- **Other engines/crawlers:** Bing, AI crawlers and social previews have their own user agents and rules; treat access policy for AI crawlers as a business decision and say which directives apply to which user agent.
